# 🎲 骰子分账

两个人各自用手机连进同一个房间，输入金额后**各掷一颗骰子**，点数比就是分账比，双方确认后记入共同账本。只记账，不碰任何真实资金。

## 快速开始

准备 Node.js 22 或 24 LTS，以及较新版本的 Safari、Chrome 或 Edge。项目没有 npm 依赖或构建步骤，直接运行服务端即可，不能直接双击 `public/index.html` 使用。

**希望长期记账时，设置口令启动：**

```bash
cd dice-split
PASSCODE='替换为足够长的随机口令' node server.js
```

**只在可信局域网临时试用时，可以不设口令：**

```bash
PASSCODE='' node server.js
```

两种命令选择一种即可，第二条同样在项目目录执行。默认端口为 `8787`，可用 `PORT=9000` 环境变量或命令行参数更改；只有设置非空口令才会保存账目，运行模式的区别见下表。前台运行时关闭终端或按 Ctrl+C 会停止服务，长期运行请使用后面的 PM2 部署步骤。

两台手机**连同一个网络**（家里同一个 WiFi；在外面就让一台手机开热点，另一台和电脑都连这个热点），分别用浏览器（iPhone 用 Safari）打开：

```
http://<电脑的局域网IP>:8787
```

电脑的局域网 IP 在 macOS 上用「系统设置 → Wi-Fi → 详细信息」查看，一般形如 `192.168.x.x`。

打开后先输入口令解锁（临时模式不需要），一方「开个房间」，把房间码或邀请链接发给对方，「加入房间」即可开始。服务端日志中的 `localhost` 只能在运行服务的电脑上访问，手机需要使用电脑的局域网 IP；两个人请使用各自的设备或独立浏览器，同一浏览器同一站点的多个标签页会共享保存的身份。

> **想加到桌面当 App 用**：iPhone Safari → 分享 → 「添加到主屏幕」，之后从桌面图标打开就是全屏界面；仍需联网访问运行中的服务，不支持离线记账。

## 运行模式与数据保留

| 项目 | 持久化模式：设置非空 `PASSCODE` | 临时模式：没有口令 |
|---|---|---|
| 网页访问 | 先验证总口令 | 直接访问，仅建议可信私网试用 |
| 磁盘数据 | 读取、保存账本文件 | 不读取也不写入账本文件 |
| 消费记录 | 保留历史，默认最多 1000 笔 | 只保留最近一笔；新消费双方确认入账后，替换旧消费及其全部还款与余额 |
| 还款记录 | 独立保留，默认最多 1000 笔 | 只显示最新一条明细，但当前消费的已确认还款仍累计抵扣；删除最新还款只撤销该笔 |
| 无人在线或服务重启 | 房间、账目、进行中分账和待确认提议可恢复 | 最后一个实时连接断开即销毁房间；服务重启也会丢失全部临时数据 |

临时房间创建后，如果 15 秒内没有任何实时连接，也会被回收。**独自刷新、关闭页面或手机断网都可能销毁临时房间**；重连只能尝试恢复连接，不能找回已经销毁的数据。临时模式删除当前消费时，也会清除对应还款与累计抵扣。

切换到无口令模式不会删除原有磁盘账本，只是不加载、不覆盖它；以后设置非空口令并使用同一数据文件启动，仍可读取原有持久化数据。

## 玩法规则

1. **记一笔**：填金额（精确到分）、备注、这次谁先垫付的。
2. **掷骰**：两人各掷一颗骰子，**点数比 = 分账比**（如 6:4 化简为 3:2）。默认六面骰（1–6 点），设置页提供 4/6/8/10/12/20 面；面数为房间共享设置，开账时锁定，须等本笔入账或作废后才能更换，只有揭晓还不能换。点数由服务端使用加密随机数生成，客户端不能自行指定；双方都掷完才一起揭晓对方点数。服务端运行者仍在信任范围内，这不是可独立验证的公平性协议。
3. **揭晓**：显示比例和各自承担的金额。金额按整数分计算，P1 按比例四舍五入，P2 承担余数，合计严格等于总金额。
4. **确认**：双方都点「记入账本」才入账；「重掷」和「作废」同样要双方同意——一方发起，对方回应，发起方可撤回。重掷不限次数，账目会记录「重掷 ×N」；提议回应与撤回绑定具体提议编号，过期请求不会批准或撤回新的提议。
5. **账本**：双方实时同步。顶部显示「对方应该给你 ¥X / 你应该给对方 ¥X」，按保留的消费记录累计垫付与承担，并抵扣双方确认的还款；手气统计只按消费计算，不受还款影响。临时模式只计算当前消费。
6. **还款 / 结清**：真实转账后点「记录还款 / 结清」，可记录部分还款或全部欠款，不能超额还款；付款方向由当前净余额确定，另一人核实后确认才抵扣。还款不改变消费的骰子结果与承担比例，本应用不会发起真实转账。
7. **删除 / 清空**：删除消费、删除还款和清空全部记录都要另一人同意，发起人可撤回，对方可拒绝。须先完成当前分账，且处理账本提议期间不能开新账；清空只针对当前房间，同时删除消费与还款，余额归零。删除或清空没有撤销功能，重要记录请事先备份。

## 运行配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | HTTP 监听端口 |
| `PASSCODE` | 空 | 非空时开启总口令与持久化；为空且未传命令行口令时使用临时模式 |
| `DICE_DATA` | 项目目录下的 `dice-split-data.json` | 持久化文件路径；建议使用绝对路径，父目录需预先存在且可写 |
| `MAX_ROOMS` | `100` | 同时保留的房间数上限，包含临时模式尚未首次连接的预留房间 |
| `MAX_HISTORY` | `1000` | 持久化模式中，每个房间的消费和还款分别受此条数限制；临时模式仍只保留各一条明细 |
| `RATE_LIMIT` | `60` | 每个来源 IP 每 60 秒内的请求上限，网页、接口和新建实时连接共用额度 |

启动格式为 `node server.js [端口] [口令]`：命令行端口优先于 `PORT`，非空 `PASSCODE` 优先于命令行口令。建议统一使用环境变量配置，限额填写正整数。应用不会自动读取 `.env`；需要通过启动环境传入，PM2 修改环境时见后文的 `--update-env`。

## 数据与维护

### 保存、备份与恢复

- **仅持久化模式写盘**，实际备份对象是 `DICE_DATA` 指定的文件，未指定时才是项目目录的 `dice-split-data.json`。其中包含所有房间、玩家身份令牌、消费、还款和进行中的状态，属于敏感数据，不要公开上传。
- 每次修改先写同目录的临时文件并落盘，再原子替换账本，成功后才通知双方；保存失败时本次修改不生效。持久化模式读取到损坏 JSON 会拒绝启动并保留原文件，不会用空账本覆盖。
- **备份**：暂停服务后，将实际数据文件复制到项目外的受保护备份目录，再启动服务；PM2 对应 `pm2 stop dice-split` 和 `pm2 restart dice-split`。复制源代码或执行 `pm2 save` 都不等于备份账本。
- **恢复**：停止服务，先另存当前数据文件，再把选定备份复制回原数据路径，检查部署用户的读写权限，然后带非空口令启动并核对房间与余额。恢复会回到备份时刻，之后新增的记录不会自动合并。
- **清空当前房间**请在界面中发起提议并由双方确认，不要为清空一间房删除整个数据文件。持久化房间不会因无人在线而自动删除。
- `.gitignore` 已排除默认账本及其临时文件、`.env` 系列文件和日志；自定义数据路径或另存的备份不一定被忽略，应放在仓库外。Git 只管理代码，不能替代数据备份。

### 刷新、断线与换设备

- 在同一设备、同一浏览器和同一站点地址下，身份保存在浏览器本地。持久化模式刷新后可重新获取账目、进行中分账及待处理提议；清除站点数据、更换域名或端口后不会自动携带原身份。
- 连接前检查遇到限流、服务异常或网络超时，会保留身份并按 1、2、4、8、16 秒退避，之后最多间隔 30 秒重试；已建立的实时流由浏览器自动重连。主动退出会停止重连，明确返回身份失效时会清除本地身份。**这不代表失败的掷骰、还款等业务请求会自动重发**，请先看同步后的状态再操作。
- 掷骰中途刷新，已掷的一方不能重复掷；揭晓前不恢复该设备暂存的具体点数，只显示是否已掷，等双方完成后一起展示结果。
- **换手机 / 清了浏览器缓存**：原房间仍存在时，用「加入房间」填写房间码；满员会显示「认领 P1/P2」，角色可在旧设备设置页查看。认领会更换该角色的身份令牌，旧令牌不能继续操作或重新连接。
- 房间最多两个角色，但不是两个独立账号。**认领只要求房间码及总口令验证（临时模式无需口令），不验证原设备所有权**，请只与可信搭子分享。认领不会主动关闭旧设备已建立的实时连接，不能把它当作完整的设备撤销机制。

## 想在外网也能用（可选）

在家里跑只覆盖同网场景。如果出门也想用，任选其一：

1. **云服务器**：将项目上传到自己的服务器，按下方 PM2 步骤后台运行，配置 HTTPS，**务必设置口令**。
2. **临时内网穿透**：本地启动服务并安装 `cloudflared` 后，另开终端运行 `cloudflared tunnel --url http://localhost:8787`，使用它输出的 HTTPS 临时地址。隧道重启后地址可能变化，本地电脑和两个进程都需保持运行；隧道暴露公网，**同样务必设置口令**。
3. **私有虚拟局域网**：三台设备安装 [Tailscale](https://tailscale.com)，通过虚拟局域网地址访问，并使用访问策略及防火墙限制访问范围，不需要把应用端口开放给整个公网。

## 使用 PM2 后台部署

以下以 Linux 云服务器为例，先安装 Node.js 22 或 24 LTS，并将项目上传到服务器。项目本身零依赖，不需要运行 `npm install` 或构建命令；PM2 用于后台运行、异常退出后重启和开机自启。

**必须使用单实例 fork 模式**（下方命令的默认模式），不要添加 `-i max`、启用 cluster 或同时启动多个实例。房间与实时连接保存在各自进程的内存中，多实例无法正确同步，也不能共同写入同一个账本文件。

### 1. 安装 PM2

```bash
npm install -g pm2
```

后续 PM2 命令使用同一个普通部署用户执行，不要混用 `sudo pm2`；开机自启时只执行 PM2 明确提示的管理员命令。

### 2. 启动应用

将下面的项目路径和示例口令替换为实际值，确保没有其他进程占用 8787 端口：

```bash
cd /path/to/dice-split
PASSCODE='替换为足够长的随机口令' PORT=8787 pm2 start server.js --name dice-split --time
pm2 status
pm2 logs dice-split --lines 50 --nostream
```

看到进程为 `online`，且日志显示口令保护已开启后，即可通过服务器地址和 8787 端口访问；公网访问请配合下方安全说明配置 HTTPS 和防火墙。若只通过反向代理访问，不要把 8787 端口直接开放到公网；PM2 本身不提供 HTTPS。

- **设置 `PASSCODE`**：启用口令保护和持久化，默认账本为项目目录中的 `dice-split-data.json`，部署用户必须对该目录有写权限。
- **未设置或设置为空**：启用临时模式，不读写账本；最后一人断开或进程重启后，房间与记录会消失。PM2 不会让临时模式的数据变成持久化数据，公网部署不要使用此模式。
- 本应用不会自动加载 `.env` 文件，环境变量须在启动时传入。不要把真实口令提交到仓库，也不要分享包含口令的终端历史或 PM2 进程备份文件（默认位于 `~/.pm2`）。

### 3. 配置开机自启

```bash
pm2 startup
```

复制并执行它输出的那条管理员命令，再保存当前进程清单：

```bash
pm2 save
```

`pm2 save` 保存的是进程清单和环境，不是账本备份；账本仍需单独备份。升级 Node.js 或更换其安装路径后，需重新配置 PM2 的开机自启。

### 4. 更新与日常维护

| 操作 | 命令 |
|---|---|
| 查看运行状态 | `pm2 status` |
| 持续查看日志（Ctrl+C 仅退出日志查看） | `pm2 logs dice-split --lines 100` |
| 更新项目文件后重启 | `pm2 restart dice-split` |
| 暂停运行 | `pm2 stop dice-split` |
| 恢复运行 | `pm2 restart dice-split` |

修改口令或端口时，要加 `--update-env` 并重新保存：

```bash
PASSCODE='替换为新的强口令' PORT=8787 pm2 restart dice-split --update-env
pm2 save
```

仅更新代码时使用普通重启即可，注意不要覆盖已有的账本文件。重启会短暂断开双方连接：持久化模式会重新加载账目，临时模式会丢失房间与记录；如果希望暂停状态在机器重启后仍然保持，执行 `pm2 stop dice-split` 后再执行 `pm2 save`。

## 🔒 安全说明（公网部署必读）

本应用按可信的两人自用场景设计，不是多租户服务或支付系统；公网部署**必须开启强口令并使用 HTTPS**。不要为了监听 80/443 端口而用 root 运行 Node，应用保留 8787 等非特权端口，由反向代理负责 HTTPS：

```bash
PASSCODE='替换为足够长的随机口令' PORT=8787 node server.js
```

| 防护 | 说明与边界 |
|---|---|
| 总口令 | 未验证时仅下发解锁页，接口和实时连接也要求验证；成功解锁可用 30 天有效的签名 Cookie 免输。总口令不是每个玩家的独立凭据，不应公开分享 |
| 限速 | 默认每 IP 每 60 秒 60 次请求，用于降低滥用风险，不保证无法枚举；经过代理时须正确处理来源 IP |
| 容量上限 | 默认最多 100 个房间，持久化模式每房最多 1000 笔消费及 1000 笔还款，限制内存和文件增长，不等于完整的抗攻击能力 |
| 提议确认 | 重掷、作废及账本操作需要双方确认，回应和撤回绑定提议编号；保护仍依赖双方身份未被他人认领 |
| 页面输出 | 昵称、备注等文本经过 HTML 转义，响应带 `X-Content-Type-Options: nosniff`；不能据此宣称应用不存在任何安全漏洞 |

### HTTPS 与实时同步代理

- 使用 Caddy、Nginx 或隧道提供 HTTPS；SSH 使用密钥登录，防火墙只开放必需的端口。使用反向代理时，限制 8787 端口只能由可信代理访问，服务自身并非只监听回环地址。
- `/events` 使用 SSE 长连接，必须及时转发响应，关闭代理缓冲和缓存，并将读取超时设置为大于 25 秒心跳间隔。Nginx 可在对应路径中设置 `proxy_buffering off;`、`proxy_cache off;`、`proxy_read_timeout 60s;`，同时确保中间 CDN 或其他代理不缓存该流。
- 服务端信任 `X-Forwarded-For` 的第一个地址。边缘代理应覆盖外部传入的该请求头，不能直接保留客户端伪造的值；Nginx 直接作为边缘代理时可用 `proxy_set_header X-Forwarded-For $remote_addr;`。多层代理需要单独配置可信来源链，不能盲目追加地址。
- 实时连接地址包含身份令牌，并可能包含口令。不要分享完整请求 URL、网络抓包或含查询字符串的代理访问日志，避免将这些内容上传到公开仓库。

## 常见问题

| 现象 | 检查方式 |
|---|---|
| 手机打不开页面 | 确认服务仍在运行、手机使用电脑的局域网 IP 而非 `localhost`、端口一致；检查 Wi-Fi 访客隔离、热点限制、防火墙以及电脑是否休眠 |
| 启动提示 `EADDRINUSE` | 端口已被占用；检查是否已有 Node 或 PM2 实例，避免重复启动，或改用其他端口 |
| 配了 `.env` 仍显示临时模式 | 应用不自动加载该文件；通过环境传入非空 `PASSCODE`，已有 PM2 进程须使用 `--update-env` 后重启 |
| 账本只剩最近一笔，或刷新后房间没了 | 先看是否为临时模式；这是该模式的数据保留规则，销毁的数据无法恢复，需长期记账时请带口令启动 |
| 显示「请求太频繁」或一直连接中 | 连接检查会自动退避重试，不要连续刷新；同一公网 IP 下多人共用限额，必要时检查代理来源 IP 配置 |
| 两端不能实时同步 | 检查 `/events` 连接是否成功、代理是否缓冲或缓存 SSE，以及各设备是否使用同一服务器；不要用多实例 cluster 运行 |
| 显示「提议已变化」 | 旧提议已被撤回或替换，请查看当前提议内容后重新选择，不要认为旧的同意已经执行 |
| 显示「账本保存失败」 | 本次修改未生效；检查日志、磁盘空间以及数据文件父目录的写权限，修复后先确认最新状态再操作，不要删除原账本来绕过错误 |
| 有口令时因数据 JSON 损坏无法启动 | 保留原文件，停服后从已核实的备份恢复；不要用空文件覆盖。无口令启动只会绕开旧数据，不会修复它 |
| 房间数或账目数达到上限 | 持久化房间不会随退出而删除，可评估后调整 `MAX_ROOMS`；消费与还款各有独立容量，可先备份再由双方清理。删除已确认记录会重新计算余额，不是无影响的归档操作 |

- `test-flow.mjs`：双人分账、还款、删除/清空确认、迟到提议请求、写入失败及重启恢复。
- `test-hardening.mjs`：口令、真实限速、容量上限、旧数据升级、损坏文件保护、临时模式的数据保留与房间回收。
- `test-client.mjs`：使用 Node 的 VM 隔离执行前端连接及按钮绑定逻辑，验证身份保留、重试、退出取消和渲染时提议编号；不启动 HTTP 服务，也不是真实浏览器测试。

前两组会自动启动随机端口服务并创建独立临时账本，结束后清理，不修改真实账目。浏览器端功能改动还应另用两台设备或独立浏览器，验证开房加入、双方掷骰确认、重掷/作废及断线恢复。
